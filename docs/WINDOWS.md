# Windows 后台服务开发版

本文件记录 x86_64 Windows 后台服务。0.1.2 包含托盘、登录面板、通知接口及完整安装/卸载包，使用方法见 [桌面说明](DESKTOP.md)。程序未签名，自动更新尚未完成。

当前代码已接入 Windows 服务、网络事件、Wi-Fi 状态、机器级 DPAPI、受限命名管道和认证核心。用户已安装旧版服务；新版安装/卸载、真实校园登录、登录界面冷启动、实际服务崩溃恢复和睡眠唤醒仍待验收。

## 运行入口

开发包中 `portal-service.exe help` 显示可用命令。`diagnose` 仅读取网络状态，不探测外网、不发送认证请求、不修改系统设置。输出包含当前网络地址和 SSID，仅供本地诊断。

管理命令：

| 命令 | 作用 |
|---|---|
| install | 管理员身份安装自动启动服务，设定恢复策略；不会当场启动认证 |
| start / stop | 管理员身份启动/停止系统服务；停止不主动注销 |
| uninstall | 停止并移除服务，保留配置、凭据和程序文件 |
| status | 读取服务状态、网络条件、成功认证序号 |
| settings | 读取设置与 has_password；不返回密码、密文、AES 密钥或缓存 |
| configure | 从标准输入读取完整的 save 请求，由服务验证并保存 |
| check / relogin | 检查或重新认证；事务进行中返回 busy，不排队重复注销 |
| login | 主动检查并认证；已在线不注销，可恢复暂停 |
| diagnose-probes | 不带凭据的直连探测，输出 HTTP、连接失败和跳转有效性 |
| pause / resume | 经 IPC 持久化暂停/恢复自动认证，不要求日常提权 |
| logs | 读取容量受限、只包含固定事件码的诊断日志 |

服务未安装时，日常命令不会启动其他进程冒充服务。`service` 是 SCM 专用入口，不能当作普通前台程序运行。

配置协议使用 UTF-8 JSON，例如请求结构为 `{"command":"save","settings":{...},"password":"..."}`。设置字段见 `crates/portal-service/src/windows/settings.rs`；省略的设置取默认值，故编辑时应先获取当前完整设置。密码为空保留已有密码。客户端不接受命令行密码参数，后续设置窗口将代替这套开发入口。

首次配置通过 `verify` 请求提交候选 settings/password/logout，立即返回 verification_id；候选凭据只保存在可清零内存中，服务完成认证和实际联网验证后才持久化。状态中的 verified_id 只在成功保存时设置为本次序号，设置面板据此决定关闭，不能使用普通 LOGGED_IN 状态代替。旧配置缺少 credentials_verified 时默认未验证，不自动拿它反复认证。开发用 save 命令不授予验证标记，改变账号密码会清除已有标记。

## 服务与权限

- 名称为 `PortalLoginer`，以 LocalSystem、正常优先级运行；自动启动且不延迟到用户登录。异常退出按 30、60、300 秒恢复，最后一档重复，失败计数一天后重置。
- 程序固定安装到系统 Program Files 下的 PortalLoginer；配置固定放在系统 ProgramData 下的 PortalLoginer。路径通过系统 Known Folder API 获取，不读取可由进程环境覆盖的路径。
- 安装目录仅系统/管理员可写，普通用户只读执行；凭据目录仅系统/管理员可访问。目录及原子写入文件的所有者固定为管理员组，避免普通用户凭所有者权限重写 DACL。安装不继承开发目录中的可写 ACL。
- 不接受预先由普通用户占有的安装/数据目录，也拒绝目录重解析点。遇到此类冲突会失败退出，不接管未知路径。
- DPAPI 使用机器作用域和禁止交互标记，允许登录前的服务解密。机器作用域本身不隔离其他用户，文件权限与所有者保护是必要组成部分。
- 新密码先写入独立、随机命名的受保护密文文件，再原子切换配置引用；失败恢复旧引用并删除新文件。异常断电最多留下孤立密文文件，不留下半份明文配置或混合的新旧凭据。
- 服务通过受限的本机命名管道通信，拒绝远程客户端。仅系统、管理员和安装时绑定的 Windows 用户可以调用，服务再次检查客户端令牌身份。
- 普通客户端没有创建新管道实例的权利。客户端发送请求前核对管道服务端 PID 与系统 SCM 记录一致，防止把密码交给抢占名称的本地进程。
- 每个请求最多 16 KiB、回复最多 64 KiB，最多 8 个并发连接，连接处理最多 8 秒；不会提供执行任意程序、读写任意路径或返回凭据的命令。

设置窗口通过安装包 `/OWNER_SID=` 将当前普通用户身份传给服务的 `setup --owner-sid`，即使使用另一管理员账号授权，也保留原用户身份。独立运行安装包不带此参数时绑定安装账户，其他账户应从开发包登录面板发起安装。此入口尚未进行实际提权安装验收。

## 网络与运行行为

从系统读取活动的物理 Ethernet/Wi-Fi 接口、IPv4、出口路由、上游 DNS。接口类型之外还检查系统 HardwareInterface 标记，不把 TUN 网卡作为认证接口。多网卡下优先当前物理出口；开启 Wi-Fi 限制后，优先目标 SSID 的 Wi-Fi，有线不触发认证。

监听接口、IPv4、路由、Wi-Fi 连接变化，并接收 SCM 电源和时间变化事件。网络/睡眠唤醒回调只取消任务、合并唤醒，不在回调内认证；系统校时只唤醒日期调度，不重置物理网络稳定期，普通电量变化不打断认证。主循环合并约 400 毫秒内的变化，创建新的网络代次和直连客户端；核心继续执行地址/出口稳定等待。监听正常时每 5 分钟兜底核对，异常时每 60 秒核对。

保存设置、暂停或停止会取消旧事务；旧网络产生的成功结果不计入新网络的认证成功事件。认证入口始终串行，普通查询可在事务期间处理。运行时最多 2 个 Tokio 工作线程和 2 个阻塞工作线程，无界面渲染循环。

Wi-Fi 信息不可读时，SSID 为未知；限制开启则等待，不猜测或降级到有线。当前 Wi-Fi 连接的配置可报告是否系统级、是否自动连接；这只表示配置条件，不等于已经证实在 Windows 登录界面可连接。密码保护、权限、系统位置设置及现场 WLAN 行为仍须实机验收。

`possible_tunnel_route` 仅表示系统默认出口不在已选物理网卡集合中，不能确定 TUN 软件类型或保证能绕过。连接失败继续按核心未知状态/退避处理。

## 日志与验证

日志不写入账号、密码、密文、密钥、SSID、MAC、URL 或原始服务器错误。只写时间、固定事件码和状态枚举；单文件约 256 KiB，保留一份旧文件，读取最近最多约 16 KiB。状态不变时不持续追加在线日志。

本轮完成 14 项 Windows 测试及原 29 项核心测试；正式构建和所有目标的 Clippy 检查通过。本机只读诊断确认可以读取物理接口和出口路由；该环境为有线，未将 Wi-Fi/登录前行为计为实测。

主循环联调使用随机命名的测试管道，在普通测试进程中模拟服务身份，仅该测试管道允许测试进程创建多个实例。生产管道不含此测试路径。实际 LocalSystem、管理员所有者写入、SCM 自动启动/恢复及登录界面认证仍待管理员安装后的现场验收。

开发包的 SHA256SUMS 只用于发现文件损坏，不是已签名更新清单。GitHub 更新、Ed25519 清单和回滚将在安装更新阶段实现。
