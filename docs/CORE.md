# Rust 核心实现与接入

本文保留核心阶段的接口设计与验证边界。已接入的 Windows 服务宿主见 [Windows 开发版说明](WINDOWS.md)，最新验证结果见 [验证记录](VALIDATION.md)。

## 本阶段结果

`portal-core` 已实现协议解析、AES 密码处理、JS 密钥识别、直连传输、认证事务及可取消的状态决策。它是供后台服务调用的库，不是已经安装的系统服务，也没有托盘或设置窗口。

固定工具链为 Rust 1.85.1；直接依赖固定版本，全部解析结果进入 Cargo.lock。当前在 Windows x86_64 GNU 工具链下编译和测试；macOS、MSVC 及校园实机尚未验证。项目内 `.tools` 是本机开发工具，不进入发布内容，不修改系统 PATH。

## 认证与调度

服务调用 `Engine::step` 执行一轮，传入受保护凭据、最新网络快照、触发原因、当地日期/小时和取消令牌。核心返回状态、下次等待时长、失败计数、是否刚完成认证、可持久化的新密钥。`Report` 不实现序列化；服务不能把它直接转发给普通客户端，因为其中可能含新密钥。

自动模式：顺序探测→有效认证跳转→按原路径识别密钥→加密一次→GET 建立 cookie→POST login→POST ack→顺序探测。只有实际 204 才产生一次 `authenticated=true`。在线轮次不会再次产生认证成功事件或改变登录时刻。无法确认探测时保留会话，不使用缓存盲目登录。

0.1.1 明确改进：手动 Login/Relogin 与自动认证均先识别当前密钥，识别失败保留已有密钥。Check 只探测；Login 遇到已联网直接结束，不主动注销。手动在线 Relogin 允许匹配缓存回退；定时注销后仍在线则结束本轮，不强制再认证。默认本地 4 点每日一次，−1 对应配置 `None`；每日标记包含完整年份，避免原 `%j` 跨年歧义。调用者须传入有效的 `YYYYMMDD` 和当地小时。

0.1.2 增加独立的首次配置事务 Verify / VerifyAndLogout。Verify 遇到在线返回 NeedsLogout，不视为凭据有效；VerifyAndLogout 仅在用户明确点击后注销，允许使用可修改的校园注销预设，IP 必须为当前地址。注销后必须重新取得有效 Portal 跳转，不接受在线缓存回退；登录返回值、ACK 与实际在线检查缺一不可。预设只可发无密码的注销请求。Check 可在暂停时明确执行，仍遵守 Wi-Fi 限制，且不恢复自动认证。

核心返回等待时间，由服务统一用 Tokio 定时器等待；核心不启动轮询线程、不写日志、不自行创建无限循环。稳定期使用单调时钟，地址/路由变化后等待约 10 秒。失败从 10 秒倍增到最多 300 秒；未知探测维持原在线探测间隔。服务收到事件后可提前唤醒。

`session_cache()` 导出与原 `last_*` 相同的子集，平台负责原子保存。`restore_cache()` 只在首次快照前接收；真正恢复时检查当前 IP，拒绝注入的查询片段。缓存不包含密码，不构成认证失效证据。服务必须对缓存限制读取权限，不把它当普通状态数据公开。

## 网络约束

1. 每个网络代次创建一个 `DirectTransport`。传入选定物理网络的 IPv4 和该网络的上游 DNS；请求与 DNS 均绑定源地址。
2. DNS 依次使用去重后的指定上游，再回退 223.5.5.5、119.29.29.29；每个上游最多约 2 秒；A 记录过滤回环、Fake-IP、链路本地、组播等结果。无有效答案才继续下一上游，不读取 hosts 或系统解析结果。
3. 保留原域名、Host/SNI 和证书验证。门户字面 IPv4 不调用 DNS。HTTP/SOCKS 环境代理由 `no_proxy()` 禁用；认证客户端不用于更新下载。
4. 探针连接/总时长 4/6 秒，JS 为 5/8 秒，API 为 8/15 秒。完整认证事务另有 120 秒截止。探针只读状态和 Location；JS 最多 256 KiB，API/门户页最多 64 KiB，含未知 Content-Length/分块体积检查。
5. login/ack/会话 GET 使用 cookie；JS、探针、logoff 不携带该 cookie，保持原入口差异。Logoff 无表单 body。所有请求均禁止跟随跳转。
6. TUN、透明代理和强制过滤仍不保证绕过。超时、异常网页和未知结果只显示未确认并等待，不据此断定 TUN 存在。

系统代理开关的实机验收留给 Windows 阶段；当前验证了隔离子进程中的代理环境变量，以及本机独立 HTTP/DNS 路径。

## 平台必须遵守的接入约定

- 服务持有唯一 Engine，通过串行队列执行命令；托盘/设置只经受限 IPC 请求操作。
- 网络接口、路由、SSID、睡眠唤醒发生变化时，先取消旧令牌，等待旧事务返回，再应用合并后的最新快照。即使 IPv4 没变，也增加 `Network.generation`，销毁旧 DirectTransport 并创建新的客户端，防止旧连接池跨网复用。
- 限制开启且 SSID 不匹配/未知/有线时不调用认证请求；暂停和网络等待由事件唤醒，监听失败时由服务提供低频兜底。
- 配置更新也先取消事务，再调用 `update_config`；传入重新读取、经过校验的完整配置。服务端负责空密码保留、凭据保护、配置原子替换、密钥保存失败的诊断和缓存去重写入。
- `subscribe()` 提供无密码的阶段状态，用于托盘与设置。成功通知依据 `authenticated` 事件去重，不依据每次 LoggedIn 状态；登录前后的补发策略由托盘和服务协商。
- 服务使用有限 Tokio 线程的运行时；核心的等待和请求不会占用持续渲染线程。实际服务线程数、空闲 CPU 和内存均待下一阶段实测。

## 已明确的实现差异

| 项目 | Rust 处理 |
|---|---|
| 不完整 URL 解析 | 先构造临时对象，全部验证后提交，不破坏旧会话 |
| 非规范 IPv4（如前导零） | 拒绝，避免 URL 库规范化后访问与校验不一致的地址 |
| 随机源故障 | 返回加密失败并退避，不使用固定随机前缀 |
| 非 ASCII 密码 | 使用 UTF-8 字节补齐；尚未在目标 OpenWrt ash 上完成兼容确认 |
| 超长 URL/响应 | 加入 URL 长度、单响应体积和整事务截止限制 |
| 密钥正则 | 保留原 HTML/缺右括号/不匹配引号边界；像原 grep 一样不跨行识别 |
| 时间与取消 | 单调等待；完整日期；定时注销中途取消也保留当日已尝试标记 |
| 诊断 | 静态类型化错误，不透传可能含凭据参数的 reqwest 错误或原始服务消息 |
| 凭据生命周期 | 核心自有密码、密钥、表单和响应缓冲区尽力清零；不承诺第三方网络库内部副本全部清零 |

JSON ret 支持明确的整数及字符串 `0/121/122/3`；布尔、数组、对象、缺字段、畸形 JSON 不接受。浮点/exponent ret 与真实 OpenWrt jsonfilter 的兼容尚无现场样例，不列为已确认。与 curl `-f` 一致，未跟随的 3xx 如携带有效 JSON body 可以参与接口结果判断；它不会触发外域请求。
