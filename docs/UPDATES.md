# 更新与镜像下载

从 0.2.11 起，客户端全程通过镜像读取本仓库 `updates/` 中的清单和更新 ZIP，不调用 GitHub Releases API，也不直接连接 GitHub 下载域名。Release 只发布一个安装包。

## 仓库文件

- `updates/manifest.json`：版本、目标平台、文件大小、SHA-256 和更新包地址。
- `updates/windows-x86_64.zip`：当前 Windows x64 更新包。

清单中的 ZIP 地址固定到保存该包的 Git 提交，避免发布新版本时把旧清单和新包混用。更新包会进入 Git 历史，仓库体积随版本增加。

## 镜像链路

1. 并发通过 GHFast、ghproxy.net、GH-Proxy 读取清单。例如 `https://gh-proxy.org/https://raw.githubusercontent.com/Small-SaltedFish/Portal_Loginer_Client/main/updates/manifest.json`。
2. 校验固定仓库、平台、版本、路径和大小，优先选择有效的最高版本；同版本选择响应较快的镜像。清单请求带缓存刷新参数。
3. 对镜像中的真实 ZIP 最多 64 KiB 片段测速，按吞吐量排序。失败自动换站；拒绝错误网页和无效 Range。
4. 支持中断续传，完整文件必须与发布清单中的 SHA-256 和大小一致。镜像重定向不允许跳回 GitHub 域名。
5. 镜像全部不可用时，只能使用此前缓存的较新版本继续下载；没有可用缓存则报告具体镜像、HTTP 错误或超时，不把失败当作已是最新版。

请求绕过普通 HTTP/SOCKS 系统代理及代理环境变量，TUN 仍由系统路由控制。镜像可用性每次实测。更新不使用私钥或额外签名，SHA-256 用于文件完整性校验。

## 安装与恢复

- 正常联网后低频检查，约每天一次并随机错开；失败 15 分钟后重试。关闭自动更新后仍可手动检查、下载并安装。
- 等待认证事务完成、设置窗口关闭、全屏或演示状态结束后安装；与安装、卸载共用互斥锁。
- 再次校验文件，只解压固定七个文件；拒绝路径穿越、符号链接、额外文件及超限解压。
- 保留上一版，逐文件原子替换，检查新服务报告的版本；失败恢复旧版。独立守护进程及开机检查处理未完成事务。
- 保留账号密码和设置，恢复托盘，不自动打开设置窗口，不再次请求管理员授权。

## 发布

依次执行 `dev.ps1 test`、`dev.ps1 build`、`package-dev.ps1 -SkipBuild`、`package-update.ps1`。提交源码后运行 `publish-release.ps1 -Publish`。

发布脚本先提交并上传 ZIP，得到固定提交地址，再发布唯一的 Setup 安装包，最后提交清单。清单只在安装包发布成功后切换；失败可以重跑，已有安装包必须与本地 SHA-256 一致，不会被静默覆盖。

**0.2.10 及以前仍使用旧更新入口，需要手动覆盖安装一次 0.2.11，此后才使用全链路镜像。** 程序暂未做系统代码签名。
