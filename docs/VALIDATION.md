## 0.1.2 首次配置与账号验证

此前“未提交账号密码”的判断仅基于不完整状态日志，不能据此否定用户已提交账号的事实。原实现确有流程问题：保存凭据后，普通在线探测即可令面板关闭，无法证明填写的账号密码被校园认证接受。0.1.2 将在线状态、认证结果、凭据持久化三个结果分开。

首次打开主动做一次只探测检查，暂停状态不恢复自动认证。已经在线且账号未验证时显示连接校园宽带 Wi-Fi、注销当前会话的提示。用户点击“注销并验证账号”后才主动注销；优先匹配当前地址的缓存，否则使用可编辑的原仓库示例预设 `http://192.168.199.200 / hn`，IP 从系统读取，不抄示例 IP/MAC/VLAN。这个预设不是已在当前校园实测通过的默认值。

注销响应成功后等待并重新探测，只有得到有效新跳转才发送候选凭据。账号登录返回值、ACK 和实际联网均须通过；ACK 成功但联网稍慢时仅复查，不重复登录。验证失败、网络变化或取消均不写入候选账号密码；旧配置保留。仅本次 verified_id 与界面请求一致且保存成功，面板才关闭并启动托盘。旧版保存的账号默认未验证，不自动拿未验证凭据反复重试。

58 项测试通过：核心 37、Windows 服务 16、桌面 5。新增测试覆盖已在线不等于账号验证、预设仅用于注销且登录必须用新参数、注销后仍在线不得提交密码、注销失败终止、ACK 拒绝时在线也不算验证、失败保留旧凭据、匹配本次保存结果才关闭面板，以及暂停时明确检查不恢复自动认证。静态检查和优化构建另行复核。

本轮仅使用构造响应和临时配置目录验证，没有用真实账号注销或认证，没有替换当前已安装服务。真实校园链路及新版安装卸载仍待实机验证。

## 0.1.4 统一退出

托盘退出改为通过已授权 IPC 取消当前任务并请求服务正常停止，等待 SCM 确认 Stopped 后关闭面板与托盘。IPC 先发送退出确认再关闭，避免回复与断开竞争；开始退出后不再调度认证。退出不会主动注销、不改变暂停设置，并保留已有有效缓存。状态订阅断开不会自动重新启动服务。

再次显式打开面板或托盘才请求启动服务。安装/升级向绑定用户授予 0x14（START、QUERY_STATUS），不授予修改配置、修改权限或删除服务的权限。服务以正常退出码报告 Stopped，按 Windows 恢复规则不属于应触发异常重启的退出。依据：https://learn.microsoft.com/en-us/windows/win32/api/winsvc/ns-winsvc-service_failure_actions_flag 。

新增真实命名管道测试覆盖收到退出确认后服务循环结束；ACL 测试覆盖绑定用户仅能启动与查询。测试不停止当前正式服务。实际 SCM 停止后重新启动、完整托盘与面板退出、管理员升级仍待安装新版后实测。网卡出口问题本轮未修复。

当前 55 项 Rust 测试通过（核心 34、桌面 4、服务 17），严格静态检查及正式优化构建通过。新版本 0.1.4 需要通过安装包更新服务启动权限后使用。
